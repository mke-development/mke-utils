# Crash Interceptor (crashInterceptor)
Модуль предоставляет базовый контракт CrashInterceptor для перехвата, обработки и логирования исключений или важных
сообщений в приложении.

## Интерфейс CrashInterceptor
Основной интерфейс для реализации перехватчиков ошибок:
- `init(logger, config)` — инициализация перехватчика с конфигурацией (опционально, зависит от реализации).
- `intercept(e: Throwable, logger, message, printStackTrace, tags)` — перехват исключений. Позволяет залогировать 
ошибку, добавить кастомное сообщение и теги.
- `message(message, logger, tags)` — отправка важного текстового сообщения (например, предупреждения), 
не являющегося напрямую Throwable.

## Готовые реализации

### 1. DevCrashInterceptor
Простая реализация для среды разработки (dev).
- **intercept**: Выводит ошибку в `logger.error(message, e)`. Автоматически склеивает переданное сообщение 
(или `e.message`) и теги в единую строку лога. Учитывает флаг `printStackTrace` для вывода стектрейса.
- **message**: Отправляет сообщение в виде `logger.warn(message)`.

### 2. TestCrashInterceptor
Реализация, предназначенная для использования в модульном тестировании. 
Предоставляет возможность проверить, какие ошибки и сообщения были перехвачены:
- Ведёт счётчики: `totalIntercepted`, `totalMessaged`, `totalEntries`.
- Сохраняет последние переданные значения: `lastThrowable`, `lastLogger`, `lastMessage`, `lastTags`.
- Выводит логи с префиксом `[test]`.
- Содержит метод `clear()` для сброса состояния между тестами.

## Конфигурация
Для передачи настроек в интерфейс используется маркерный интерфейс `CrashInterceptorConfig`. 
Для реализаций по умолчанию используется пустой конфигуратор `CrashInterceptorConfigImpl`. Сторонние реализации 
(например, для Sentry) могут использовать этот интерфейс для передачи специфичных параметров.
